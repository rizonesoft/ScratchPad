## Diagnosis (implementer record, items 2-4)

### Item 2: the named renderer difference (track B)

**Cross-DPI rasterization noise** (the README's own term): the committed goldens were rendered at 150% device DPI and downscaled to canonical 900x650, while CI renders natively at 100% (the 1024x768 runner screen cannot place a 125%+ window, so scale 1.0 is proven by placement succeeding at all). Glyph rasterization (hinting, stem snaps) differs by DPI, so downscaled-150% glyph edges differ from native-100% glyph edges at the same canonical coordinates with large per-channel deltas. The README's tolerance baseline measured this noise at 128px (0.031%) on the sparse §1 shell; the 09-16 chrome landings (menu bar, tabs, status bar, settings controls) multiplied the exposed text edges, growing the same physics to 1128px (0.225%) and 3414px (0.682%). Threshold-raising is mathematically ruled out: CI noise (3414px) now exceeds the 10px-shift guard signal (736px per README, 2550px re-measured on current stock).

Side-by-side pixel evidence (HEAD run 35201002875 artifacts vs committed goldens, comparer replicated in PIL to exact CI counts):

| ---- | ------ | ----------- | ------ | -------------- |

Killed alternatives, each with pixel evidence:

- Mica present/absent: dead. Backdrop center red channel is mean 45.0 stdev 0.00 on BOTH golden and CI fresh; no Mica noise either side.
- ClearType vs grayscale text: dead. Inter-channel spread at diff pixels is 0.0-2.8 on both sides (0-2% fringed); both render all-gray edges.
- Global misregistration: dead. Integer shift search over dx,dy in [-4,4] makes every count worse (MAIN best non-zero shift 1292 vs 1128; SETTINGS 3384 vs 3414).
- Pure resample phase (no rasterization difference): dead. 150%-roundtrip and 2px-slop resampling of the fresh capture induce 0 delta>96 pixels; resampling alone cannot explain flips like golden 65 vs fresh 231 at adjacent pixels.
- Confirming: half-res collapse 15-18x (MAIN 0.225% to 0.017%, SETTINGS 0.682% to 0.038%) proves single-pixel-edge phenomena, and golden edges are softer than fresh (1506 vs 898 soft-fringe pixels), proving the golden side was downscaled from higher DPI.

### Item 3: fix and rejected alternatives (track B)

Chosen: 3x3 box blur of both images inside `GoldenComparer.Compare` before the pixel loop, plus a `capture: scale=X raw=WxH` line in `UiCapture` test output so the next diagnosis starts from numbers. Measured on real CI pixels (PIL replica of the comparer, exact CI counts reproduced first): MAIN 1128 to 18px, SETTINGS 3414 to 21px, 10px shift still 1069px against the 500px threshold. Delta 96 and 0.1% stand unchanged. Corroboration for CI scale 1.0 beyond the placement proof: the retired telemetry section of `docs/testing.md` (removed 2026-09-17) recorded "CI renders 800x600 dark at 100% DPI".

Rejected: raising `maxDifferentFraction` (mathematically ruled out: CI noise 3414px exceeds the 10px-shift signal, so any clearing threshold blinds shift detection); re-capturing goldens at 100% (moves the same failure to dev machines at 150%, needs a 100% capture host, and would force a fail-fast scale gate that makes golden tests un-runnable for most developers); half-resolution compare (cruder than blur, weakens all future sensitivity instead of just edge phase).

Durable pin: `OnePixelEdgeWobblePassesComparison` (synthetic 1px bar offset, 1158px raw-red pre-fix by construction, green post-fix) joins the existing `TenPixelShiftFailsComparison` guard (still red post-fix): normalization pinned from below, sensitivity pinned from above.

### Item 4: UI-functional diagnosis and fix (track C)

Named cause: Explorer extension-hiding. CI runner profiles default to `HideFileExt` 1 while dev boxes show (0); the Common Item Dialog honors the setting in its File name box and file list. All 6 HEAD failures reproduced locally by flipping that one bit, with byte-identical signatures (`unsaved work.txt` vs `unsaved work`, list item unfound in 24s, save misrouted so the target never lands). Not an app bug, not a test bug: an environment precondition of the same class as the dark-theme keys already in `build.yml`.

Fix: `build.yml` gains a `Show file extensions` step (`HideFileExt` 0) beside the theme step, and `docs/testing.md` gains a UI suite preconditions section (theme + extensions with verify commands). Rejected: making the six tests hiding-agnostic (exact displayed names are the point of those assertions; the precondition keeps them strict). Also fixed while there: the 2026-09-17 testing-doc edit dropped the word telemetry ("CI runs were retired" contradicts the gating build workflow); restored with the commit message as evidence.
